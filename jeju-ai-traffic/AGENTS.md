# AGENTS.md — Codex 앱 작업 규칙 (v0.3)

## 목적 및 우선순위
제주 AI 교통 경로 추천 웹서비스의 승인된 MVP만 개발한다. 우선순위: `PRD.md`(확정 원본, 수정 금지) > `IMPLEMENTATION_PLAN.md`(기술 제안은 미확정) > 이 파일 > `tasks/TASK-XXX.md` > `README.md`. 충돌·미결정 사항은 추정하지 말고 질문한다.

## Codex 앱 대화 프로토콜
사용자가 이 프로젝트에서 **`시작`**, **`다음`**, **`상태`**, **`계획 승인`**, **`완료 승인`** 등의 짧은 메시지를 보내면 다음 규칙을 적용한다. 단어만으로 실행 승인을 추정하지 않는다.
1. 매 응답 전 `START_HERE.md`, `TASK_STATUS.md`, `DECISIONS.md`를 확인한다. 현재 TASK는 `TASK_STATUS.md`에 기록된 작업만 사용한다. 상태가 불명확하면 실행하지 않는다.
2. `시작`/`다음`: 현재 TASK가 `대기`면 PRD·구현계획·대상 TASK를 읽고 **읽기 전용 계획**을 제시한다. 이 단계에서 코드·문서·상태 파일 수정, 외부 API 호출, 설치·배포를 하지 않는다. 사용자에게 **`계획 승인: TASK-XXX`**라는 명시적 응답을 요청한다.
3. `계획 승인: TASK-XXX`: 대상 TASK가 `계획 검토`이고 사용자가 해당 계획을 승인했을 때만 작업을 실행한다. 실행 승인은 현재 TASK 범위의 로컬 변경·허용된 테스트에 한정한다. 외부 유료 API 호출, 계정/결제 등록, 비밀키 사용, 실제 배포는 별도 명시적 승인이 필요하다.
4. 실행 중 TASK 범위를 벗어나거나 전제가 달라지면 멈추고 원인·선택지를 보고한다. 다음 TASK를 자동 실행하지 않는다.
5. 작업 완료 시 `reports/TASK-XXX-RESULT.md`에 변경 파일·구현 요약·수용 기준·테스트/빌드 결과·실패·비용/보안 위험·남은 이슈를 기록하고, `TASK_STATUS.md`를 **결과 검토**로 바꾼다. 사용자의 완료 승인을 기다린다. 실행 종료만으로 완료로 간주하지 않는다.
6. `완료 승인: TASK-XXX`: 사용자가 결과를 명시적으로 승인하고 현재 상태가 `결과 검토`인 경우에만 현재 TASK를 `완료`로 기록하고 다음 TASK를 `대기`로 지정한다. **다음 TASK의 계획 생성이나 구현은 자동 시작하지 않는다.** `다음` 메시지를 기다린다.
7. `상태`: 파일 변경 없이 현재 TASK·승인 대기 상태·다음 행동을 설명한다. `보류`/`반려`: 진행하지 말고 수정 계획을 요청한다.
8. `승인` 한 단어만 받으면 계획 승인인지 완료 승인인지 명확하지 않은 경우 확인 질문을 한다. 앱 UI의 파일 접근/명령 실행 승인과 TASK 계획·결과 승인은 **서로 다른 승인**이다.

## 변경 및 안전
- 한 번에 하나의 TASK만. `TASK_STATUS.md`의 상태는 **사용자 승인 근거가 있는 경우에만** 갱신한다. 승인 문구와 날짜는 `DECISIONS.md`에 기록한다. 사용자 메시지에 없는 승인을 지어내지 않는다.
- `TASK-001`은 P0 기술·비용 조사만 수행하며 코드 스캐폴딩 금지. 실제 제주 경로/교통 API, 무료 한도 및 과금 방지 검증이 불충분하면 TASK-002 진입을 보류하고 결정 요청.
- API 키, 정확한 위치정보, 비밀번호, 토큰을 코드/로그/커밋에 남기지 않는다. `.env.example`은 키 이름만 기록한다.
- 월 운영비 0원 제약이 AI 설명과 5분 재평가보다 우선. 자체 호출 카운터만으로 공급자 과금 차단을 보장하지 않는다.
- 확인되지 않은 정체·사고·예상시간을 생성하지 않는다. FR-012, 네이티브 내비, 외부 내비 실행 중 백그라운드 감시는 MVP 제외.
- 테스트 미실행/실패는 성공으로 보고하지 않는다. 새 프로젝트이므로 폴더 구조·명령은 기술 확정 및 해당 TASK 이후에만 구체화한다.
