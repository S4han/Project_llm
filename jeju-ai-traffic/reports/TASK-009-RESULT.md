## 2. 구현 요약
- **제어기(`Monitor`)**: 시계·타이머·화면 상태·위치·조회를 주입받는 순수 TypeScript 클래스. 시작하면 즉시 1회 재평가하고, 재평가가 **끝난 시점부터 300초** 뒤 다음 회차를 예약한다(일찍 실행 없음, 허용 오차 +15초는 브라우저 타이머 지연 범위). 진행 중에는 새 요청을 하지 않는다.
- **활성 조건**: 모니터링 켬 + `visibilityState === "visible"` + 위치 확인(정확도 200m·제주 안) + 서버 허용. 화면이 숨겨지면 타이머를 지우고, 다시 보이면 마지막 종료로부터 300초가 지났으면 즉시 1회, 아니면 남은 시간만큼 예약한다.
- **회차 처리**: 현재 위치 1회 요청 → 목적지 200m 이내면 '도착' 중지 → `POST /api/routes/compare`(`purpose: "reevaluation"`) → 성공 시 결과·마지막 성공 시각 갱신, 실패 시 실패 1회. 위치 부정확·시간 초과도 실패 1회, 위치 권한 없음은 중지.
- **중지 조건**: 사용자 중지, 도착, 연속 3회 실패, `QUOTA_BLOCKED`(즉시, 이후 호출 없음), 위치 권한 없음, 60분 경과. 중지 후 '다시 시작' 가능, 마지막 성공 결과는 유지.
- **서버**: `purpose: "reevaluation"`이면 TASK-003의 재평가 기준(카카오 6,000건 이상이면 차단)을 적용하고, 직접 조회는 8,000건까지 허용한다. 알 수 없는 값은 직접 조회로 본다.
- **화면**: 시작 전 동작 조건 안내(화면 켜짐·페이지 열림, 비활성 시 멈춤, 최대 60분), 진행 중 "다음 갱신 약 N분 후"/"재평가 중…"/비활성 멈춤 안내, 실패 시 "갱신 실패: 사유 · 마지막 성공 HH:MM", 중지 사유·재사용 시각·마지막 성공. 비교: "선택 경로(같은 방식으로 다시 조회) X: 남은 예상 N분", 가장 빠른 경로와 차이, 규칙 기반 설명 한 줄. 재평가 결과로 AI 설명은 요청하지 않는다(최초 조회의 '추천 이유'는 그대로).

## 6. 남은 이슈
1. **'기존 경로'는 근사**: 같은 호출 방식으로 다시 받은 경로라 처음 경로와 실제 도로가 다를 수 있다(카카오에 경로 식별자 없음).
2. **실기기 미검증**: 모바일 Safari의 화면 잠금·앱 전환 시 `visibilitychange` 동작, 절전 중 타이머 지연은 실기기 확인이 필요하다(TASK-011 권장).
3. 사용량 카운터는 인스턴스별(기존 한계).
4. 5분 이상 단축 시 변경 안내·알림·중복 억제는 TASK-010.
