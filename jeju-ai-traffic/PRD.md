## 2. 제품 개요

제주도 운전자가 출발 전 복수 경로의 예상 소요시간과 교통상황을 비교하고, AI가 제공하는 근거 설명을 참고하여 예상 소요시간이 가장 짧은 경로를 선택하도록 지원하는 웹서비스다. 웹페이지가 활성 상태인 동안 5분마다 교통상황과 잔여 경로를 재평가하고, 대체 경로가 현재 경로보다 **5분 이상** 빠를 것으로 예상되면 경로 변경을 안내한다. 길 안내는 외부 내비게이션에 목적지를 전달하는 방식으로 연결한다.

**서비스의 경계:** 자체 턴바이턴 내비게이션이 아니며, 외부 내비게이션이 전면 실행되는 동안 웹서비스의 백그라운드 위치 추적·교통 감시를 보장하지 않는다. 실제 경로·교통 데이터 제공 범위는 검증 필요하다.

## 3. 문제와 목표 (STEP 1)

### 3.1 해결할 문제

- 제주도에서 주말 등 교통량이 많은 시간대에는 평화로, 1100도로, 516도로와 같은 대체 경로 중 어느 길이 실제로 빠른지 판단하기 어렵다.
- 출발 시점의 정체·사고·통제 상황이 경로별 예상 소요시간에 어떤 영향을 주는지 한눈에 비교하기 어렵다.
- 운행 중 교통상황이 변했을 때 기존 경로를 유지할지 다른 경로를 선택할지 판단할 근거가 부족하다.

### 3.2 대표 이용 상황

제주시에서 서귀포 천지연폭포로 이동하려는 운전자가 평화로·1100도로·516도로 등 API가 실제 제공하는 경로를 비교한다. 이 도로들이 항상 모두 조회된다는 뜻은 아니다. 운전자는 출발 전에 최단시간 경로를 확인하고, 웹서비스가 활성 상태인 동안 교통 변화에 따른 경로 재평가 결과를 확인한다.

### 3.3 주요 사용자 및 목표

- **주요 사용자:** 제주도 내 자동차 운전자.
- **사용자 목표:** 출발지와 목적지에 맞는 복수 경로를 비교하고, 확인 가능한 교통상황을 반영한 최단 예상시간 경로를 선택한다.
- **핵심 가치:** 경로 선택의 판단 근거를 제공하고, 교통상황 변화 시 유의미한 대체 경로를 식별한다.

### 3.4 성공 기준 (지표 정의; 목표값 미결정)

| 지표 | 측정 방법 제안 | 목표값 |
|---|---|---|
| 예상시간 정확도 | 실제 도착시간 대비 최초·재평가 예상시간 오차 | 미결정 |
| 경로 변경 효용 | 변경 제안 후 예상·실제 단축시간, 사용자 수용 여부 | 미결정 |
| 경로 비교 성공률 | 유효 요청 중 경로 비교 결과 제공 비율 | 미결정 |
| 교통정보 최신성 | 원천 데이터 시각과 화면 표시 시각 간 차이 | 미결정 |
| 재평가 실행률 | 활성·호출 허용 상태에서 예정된 재평가 중 실행 비율 | 미결정 |
| 비용 정책 준수 | 월간 유료 청구 발생 여부 | **0원** |

목표 수치, 측정 데이터 수집 방식 및 개인정보 영향은 출시 전 별도 결정한다.

### 4.2 해소된 요구사항 충돌

1. **5분 재평가 vs 무료 한도:** 정상적인 활성·호출 허용 상태에서는 5분 주기로 재평가하지만, 과금 위험이 있으면 요청을 중단하고 이유 및 마지막 성공 조회 시각을 표시한다.
2. **MVP AI 설명 vs 무료 AI 한도:** AI 호출을 중단하고 검증된 경로 데이터를 바탕으로 규칙 기반 설명을 제공하되, 설명 출처를 구분한다.
3. **선택 경로 vs 외부 내비게이션:** 목적지 전달을 필수로 하며 외부 내비게이션이 다른 경로를 제시할 수 있음을 고지한다.

## 5. 핵심 사용자 시나리오 (STEP 3)

### US-001 — 출발 전 복수 경로 비교

- **시작:** 사용자가 제주도 내 목적지로 이동하려고 웹서비스에 접속한다.
- **목표:** 가장 짧은 예상 소요시간의 경로를 파악한다.
- **흐름:** (1) 현재 위치 사용 또는 출발지 직접 입력 → (2) 목적지 검색·선택 → (3) 복수 경로 조회 → (4) 예상 소요시간 비교 및 최단시간 경로 표시 → (5) 사용자가 경로 선택.
- **완료 조건:** 유효 경로와 예상 소요시간을 비교하여 선택할 수 있다.
- **관련 기능:** FR-001~004, FR-007.

### US-002 — 경로별 정체 및 AI 분석

- **시작:** 사용자가 추천 경로의 정체·사고·통제 영향과 추천 이유를 확인하려 한다.
- **흐름:** (1) 확보 가능한 교통정보 조회 → (2) 경로와 구간 정보 연결 → (3) 확인된 상황·미확보 구간 표시 → (4) AI가 실제 수치와 확인된 사실만으로 설명; AI 사용 불가 시 규칙 기반 설명.
- **완료 조건:** 경로별 교통상황과 추천 근거를 이해할 수 있다.
- **관련 기능:** FR-005~007, FR-011.

### US-003 — 외부 내비게이션 연결

- **시작:** 사용자가 선택 경로를 확인하고 실제 길 안내를 시작하려 한다.
- **흐름:** (1) 경로 선택 → (2) 외부 내비게이션 연결 요청 → (3) 목적지 전달 → (4) 외부 내비게이션에서 경로 확인 후 길 안내 시작.
- **완료 조건:** 목적지 정보가 전달되어 사용자가 외부 내비게이션에서 길 안내를 시작할 수 있다.
- **제약:** 선택 경로 그대로 재현되는 것은 보장하지 않는다.
- **관련 기능:** FR-008.

### US-004 — 웹서비스 활성 상태에서 경로 재평가

- **시작:** 사용자가 웹페이지를 활성 상태로 유지하며 이동하고 모니터링을 시작했다.
- **흐름:** (1) 최초 조회 → (2) 정상·호출 허용 상태에서 5분마다 현재 위치와 교통정보 재조회 → (3) 기존 경로와 대체 경로의 **남은** 예상 소요시간 비교 → (4) 5분 이상 단축 가능 시 변경 안내 → (5) 사용자가 유지·변경 결정.
- **완료 조건:** 의미 있는 단축 가능성을 판단할 수 있다.
- **제약:** 페이지 비활성화, 위치 접근 제한, 네트워크 오류, 무료 한도 도달 시 재평가를 보장하지 않는다.
- **관련 기능:** FR-009~011.

## 6. 기능 요구사항과 수용 기준 (STEP 4)

> 우선순위 Must/Should/Could는 기능의 중요도를, MVP 포함 여부는 이번 버전의 구현 범위를 나타낸다. 각 AC는 검증 가능한 기대 결과이며, 외부 API 지원 여부가 미검증인 부분은 별도 의존성으로 관리한다.

### FR-001 출발지 설정 — Must / MVP 포함

- **설명:** GPS 현재 위치 또는 사용자가 입력한 출발지 설정.
- **가치:** 실제 출발지 및 가상의 출발지 모두 비교 가능.
- **수용 기준:**
  - AC-001-01: 사용자가 현재 위치 사용을 선택하고 권한을 허용하면 획득한 위치를 출발지로 설정한다.
  - AC-001-02: 권한을 거부해도 수동 입력을 제공한다.
  - AC-001-03: 수동 출발지를 선택하면 해당 위치를 기준으로 경로를 조회한다.
  - AC-001-04: 출발지가 유효하지 않으면 경로 조회를 차단하고 수정 안내를 표시한다.
- **시나리오:** US-001, EX-001, EX-007. **의존성:** 브라우저 위치 API, 지오코딩/검색 API.

### FR-002 목적지 검색 및 선택 — Must / MVP 포함

- **설명:** 제주도 내 장소 또는 주소 검색과 목적지 선택.
- **가치:** 원하는 이동 목적지 지정.
- **수용 기준:**
  - AC-002-01: 검색어에 대한 장소·주소 결과를 표시한다.
  - AC-002-02: 결과를 선택하면 목적지 위치정보를 설정한다.
  - AC-002-03: 결과가 없으면 결과 없음 상태를 표시한다.
  - AC-002-04: 목적지를 선택하지 않으면 경로 조회를 실행하지 않는다.
- **시나리오:** US-001. **의존성:** 장소 검색/지오코딩 API.

### FR-003 복수 경로 조회 — Must / MVP 포함

- **설명:** 출발지·목적지 간 API가 제공하는 유효 경로와 예상 소요시간 조회.
- **가치:** 대안 비교.
- **수용 기준:**
  - AC-003-01: 유효한 출발지·목적지 설정 후 경로 조회를 요청한다.
  - AC-003-02: 복수 유효 경로를 받으면 각 경로의 예상 소요시간을 표시한다.
  - AC-003-03: 경로가 하나이면 단일 경로와 대체 경로 없음 상태를 표시한다.
  - AC-003-04: 조회 실패 시 오류 안내와 호출이 허용되는 경우 재시도 기능을 제공한다.
  - AC-003-05: 조회 시각 또는 예상시간의 기준 시점을 표시한다.
- **시나리오:** US-001, EX-003, EX-004. **의존성:** 교통 반영 경로 API, 무료 호출 허용 상태.

### FR-004 최단시간 경로 추천 — Must / MVP 포함

- **설명:** 유효 경로 중 가장 짧은 예상 소요시간의 경로 표시.
- **가치:** 경로 선택 시간 단축.
- **수용 기준:**
  - AC-004-01: 조회된 모든 유효 경로의 예상 소요시간을 비교한다.
  - AC-004-02: 최솟값인 경로를 최단시간 추천 경로로 표시한다.
  - AC-004-03: 다른 경로와의 예상시간 차이를 계산해 표시한다.
  - AC-004-04: 동률인 경우 동률을 표시하거나 확정된 동률 처리 규칙을 적용한다(규칙 미결정).
- **시나리오:** US-001, EX-004. **의존성:** FR-003.

### FR-005 경로별 교통상황 분석 — Must / MVP 포함

- **설명:** 정체·사고·통제 등 확보 가능한 교통정보를 경로에 연결.
- **가치:** 추천 경로의 근거 이해.
- **수용 기준:**
  - AC-005-01: 교통정보 원천의 구간 데이터를 조회 경로에 연결한다(매칭 방법 검증 필요).
  - AC-005-02: 확인된 정체·사고·통제를 해당 경로에 표시한다.
  - AC-005-03: 미제공 구간은 '정상 소통'이 아닌 '정보 미확보'로 구분한다.
  - AC-005-04: 교통정보 API 실패 시에도 유효한 경로 비교 결과는 제공한다.
- **시나리오:** US-002, EX-002. **의존성:** FR-003, 제주 교통정보 API, 구간 매칭.

### FR-006 AI 추천 이유 설명 — Should / MVP 포함

- **설명:** 경로·교통정보를 근거로 자연어 설명을 생성하고, AI 불가 시 규칙 기반 설명으로 대체.
- **가치:** 경로 추천 결과를 이해하기 쉬움.
- **수용 기준:**
  - AC-006-01: AI는 경로 API의 예상시간을 임의 변경하지 않는다.
  - AC-006-02: 확인된 교통상황과 실제 경로 간 시간 차이를 근거로 설명한다.
  - AC-006-03: 미제공 사고·정체·통제를 사실처럼 생성하지 않는다.
  - AC-006-04: AI 실패·지연 시에도 기본 경로 비교를 유지한다.
  - AC-006-05: AI 무료 한도 소진 시 AI 호출을 중단한다.
  - AC-006-06: 확인된 경로 데이터를 활용한 규칙 기반 설명을 제공한다.
  - AC-006-07: 규칙 기반 설명과 AI 생성 설명을 명확히 구분해 표시한다.
- **시나리오:** US-002, EX-008. **의존성:** FR-003~005, AI API 무료 한도, 설명 검증 로직.

### FR-007 지도 기반 경로 표시 — Must / MVP 포함

- **설명:** 지도에서 경로별 형상을 구분해 표시.
- **가치:** 공간적으로 경로를 비교.
- **수용 기준:**
  - AC-007-01: 유효한 경로 좌표가 있으면 지도에 경로를 표시한다.
  - AC-007-02: 선택 경로와 대체 경로를 시각적으로 구분한다.
  - AC-007-03: 선택 경로가 변경되면 강조 표시도 변경된다.
  - AC-007-04: 지도 표시 실패 시 확인 가능한 경로·시간 텍스트를 제공한다.
- **시나리오:** US-001, US-002. **의존성:** FR-003, 지도 API/라이브러리, 경로 좌표.

### FR-008 외부 내비게이션 연결 — Must / MVP 포함

- **설명:** 선택한 목적지를 지원되는 외부 내비게이션에 전달.
- **가치:** 기존 내비게이션에서 길 안내 시작.
- **수용 기준:**
  - AC-008-01: 길 안내 시작을 선택하면 지원되는 외부 내비게이션 연결을 시도한다.
  - AC-008-02: 연동이 허용하는 목적지 정보를 전달한다.
  - AC-008-03: 외부 내비게이션의 경로가 웹서비스에서 선택한 경로와 다를 수 있음을 안내한다.
  - AC-008-04: 연결 실패 시 목적지 복사 또는 수동 검색을 안내한다.
  - AC-008-05: 지원되는 연동 환경에서 목적지 정보가 전달되는지 검증한다.
  - AC-008-06: 선택 경로의 동일 재현을 필수 성공 조건으로 요구하지 않는다.
- **시나리오:** US-003, EX-005. **의존성:** 내비게이션별 공식 딥링크/URL 연동, 기기 테스트.

### FR-009 교통상황 재평가 — Must / MVP 포함

- **설명:** 활성 웹페이지에서 5분마다 위치·교통정보 기반 남은 경로 재평가. 무료 한도 제약 우선.
- **가치:** 이동 중 교통 변화 파악.
- **수용 기준:**
  - AC-009-01: 사용자가 모니터링을 시작하면 최초 재평가를 실행한다(호출 허용 조건).
  - AC-009-02: 정상·활성·호출 허용 상태에서 시작 후 5분마다 재평가 요청을 실행한다(허용 오차 미결정).
  - AC-009-03: 위치가 바뀌면 다음 재평가에서 변경된 위치를 반영한다.
  - AC-009-04: 기존 경로와 대체 경로의 남은 예상 소요시간을 재비교한다.
  - AC-009-05: 사용자가 중지하면 이후 자동 재평가 요청을 중단한다.
  - AC-009-06: 웹페이지 비활성화 시 지속 감시가 보장되지 않음을 안내한다.
  - AC-009-07: 오류·단절 시 갱신 실패와 마지막 성공 조회 시각을 표시한다.
  - AC-009-08: API 무료 한도 도달 또는 과금 위험 감지 시 자동 재평가를 중단한다.
  - AC-009-09: 재평가 중단 사유와 마지막 성공 조회 시각을 표시한다.
- **시나리오:** US-004, EX-006, EX-007. **의존성:** FR-001, FR-003~005, 비용 제한 장치, 브라우저 활성 상태.

### FR-010 유의미한 경로 변경 안내 — Should / MVP 포함

- **설명:** 대체 경로의 남은 예상 소요시간이 기존 경로보다 5분 이상 짧으면 변경을 안내.
- **가치:** 실질적 시간 절감 기회 파악.
- **판단식:** 예상 단축시간 = 기존 경로 잔여 예상시간 − 대체 경로 잔여 예상시간. **예상 단축시간 ≥ 5분**이면 안내 대상.
- **수용 기준:**
  - AC-010-01: 3분 단축 시 변경 안내하지 않는다.
  - AC-010-02: 4분 59초 단축 시 변경 안내하지 않는다.
  - AC-010-03: 정확히 5분 단축 시 변경을 안내한다.
  - AC-010-04: 8분 단축 시 변경을 안내한다.
  - AC-010-05: 대체 경로가 느리면 변경 안내하지 않는다.
  - AC-010-06: 사용자가 거부하면 현재 선택 경로를 유지한다.
  - AC-010-07: 동일 상황의 반복 안내는 확정된 중복 방지 규칙에 따라 억제한다(규칙 미결정).
- **시나리오:** US-004. **의존성:** FR-009, 중복 알림 방지 규칙.

### FR-011 오류 및 데이터 최신성 표시 — Must / MVP 포함

- **설명:** 오류·정보 미확보·오래된 정보·호출 제한 상태의 명확한 안내.
- **가치:** 데이터 신뢰 상태를 알고 판단.
- **수용 기준:**
  - AC-011-01: 교통정보 미제공 시 '정보 미확보'로 표시한다.
  - AC-011-02: 경로 API 오류 시 안내 및 허용 가능한 경우 재시도를 제공한다.
  - AC-011-03: 갱신 실패 시 마지막 성공 조회 시각을 표시한다.
  - AC-011-04: 위치 권한 거부 시 수동 입력을 제공한다.
  - AC-011-05: GPS 정확도 부족 시 재확인을 안내한다.
  - AC-011-06: AI 실패 시 기본 경로 비교 결과를 유지한다.
  - AC-011-07: 교통정보가 없다는 사실을 정체가 없다는 뜻으로 표현하지 않는다.
  - AC-011-08: 네트워크 복구 후 사용자가 재시도하거나 다음 허용된 재평가를 진행할 수 있다.
  - AC-011-09: 호출 제한 중인 데이터는 최신 정보로 표시하지 않는다.
- **시나리오:** EX-001~008. **의존성:** FR-001~010, 조회 시각 및 상태 관리.

### FR-012 최근 검색 경로 저장 — Could / MVP 제외

- **설명:** 사용자가 동의한 출발지·목적지 조합을 저장·재사용.
- **가치:** 반복 검색 편의성.
- **향후 수용 기준:**
  - AC-012-01: 저장 동의 경로를 최근 검색 목록에 추가한다.
  - AC-012-02: 저장된 경로 선택 시 출발지·목적지를 설정한다.
  - AC-012-03: 저장된 경로를 삭제할 수 있다.
  - AC-012-04: 재조회 시 최신 경로 정보를 요청한다.
- **시나리오:** US-001. **의존성:** FR-001, FR-002, 저장·삭제 정책 미결정.

## 11. 가정과 미결정 사항

### 11.1 합의된 운영 전제

- 실제로 경로·교통 데이터가 제공되는 범위에서만 결과를 표시한다.
- 경로 API가 하나의 경로만 제공하면 임의로 복수 경로를 만들어내지 않는다.
- 웹페이지 활성 상태 및 API 호출 허용 조건에서만 5분 재평가를 기대한다.
- 월 0원 제약이 재평가·AI 호출보다 우선한다.
- 외부 내비게이션은 목적지만 전달하며 선택 경로 재현은 보장하지 않는다.

### 11.2 미결정 목록

| 분류 | 항목 | 처리 시점/방법 |
|---|---|---|
| 제품 | 정식 제품명 | 최종 명칭 결정 시 |
| 성공 지표 | 예측 오차·효용·가용성 목표값 | 시험 운용·측정 설계 후 |
| 경로 | 실제 경로 API, 복수 경로 지원, 동률 처리 | API 검증 및 상세 설계 |
| 교통 | 데이터 공급자, 주요 도로 범위, 구간 매칭 정확도 | 실호출 검증 |
| 지도 | 지도 공급자·표시 방식·무료 한도 | 기술 검증 |
| AI | 모델, 무료 한도, 사실 검증 방식, 응답 제한시간 | 기술 검증 |
| 비용 | 공급자별 내부 허용 호출 수, 안전 여유분, 계정 단위 청구 차단 | 출시 전 필수 |
| 재평가 | 5분 타이머 허용 오차, 중복 요청·지연 처리 | 상세 설계 |
| 알림 | 동일 대체 경로 중복 알림 억제 규칙, 화면 알림 UX | 상세 설계 |
| 최신성 | 데이터가 오래되었다고 판단할 시간 임계값 | 원천 갱신 주기 확인 후 |
| 내비 | 지원 외부 내비 종류 및 연동 실패 처리 세부 방식 | 실제 기기 검증 |
| 개인정보 | 위치정보 수집·전송·보관·삭제, 동의 문구 | 출시 전 검토 |
| 브라우저 | 지원 iOS Safari 및 기타 브라우저 범위 | 테스트 계획 |
| 개발 | 최종 프론트엔드·백엔드·호스팅 기술 | 설계 단계 |
| 안전 | 운전 중 조작 최소화 및 알림 표현 규칙 | UX 검토 |

미결정 사항은 확정된 사실로 취급하지 않는다. 특히 API의 실제 무료 제공량과 제주도 교통 데이터 품질은 검증되지 않았다.
